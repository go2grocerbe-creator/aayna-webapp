# AAYNA Launch SEO Audit (L4)

SEO, domain, and route-integrity hardening ahead of production deployment.
Builds on the real-data storefront (M4.1–L3.1) and environment isolation
(L1/L1.1). No redesign, no catalogue change, no payment/delivery/contact
change, no deploy, no merge — see `LAUNCH_SETTINGS_BASELINE.md` and
`LAUNCH_CATALOGUE_BASELINE.md` for what launch actually sells and how it's
priced; this document only covers how it's found and previewed.

## 3. Robots.txt & sitemap.xml

Both are dynamically generated by the backend (`backend/server.py`,
Milestone 3G, `_render_robots()` / `_render_sitemap()`), dual-mounted at
`/api/robots.txt`+`/robots.txt` and `/api/sitemap.xml`+`/sitemap.xml`.

**robots.txt** — verified live, unchanged this milestone (already correct):
```
User-agent: *
Allow: /
Disallow: /admin
Disallow: /cart
Disallow: /checkout
Disallow: /order-confirmation
Disallow: /api/admin
Disallow: /api/auth

Sitemap: {PUBLIC_SITE_URL}/sitemap.xml
```
`/track-order` is intentionally **not** disallowed here — the route stays
publicly reachable (customers use it); only its indexability changed (§7).

**sitemap.xml** — fixed this milestone. `SITEMAP_STATIC_PATHS` no longer
includes `/track-order` (§7). Category and product entries are now scoped
to `LAUNCH_CATEGORY_SLUGS = {earrings, necklaces, rings}` — the same
launch-scope allowlist the frontend already enforces in

Gift Sets are real, active, undeleted catalogue, but not launch-promoted;
their pages are noindex on the frontend (§7/§8), so leaving them in the
sitemap would have sent crawlers a "here's a page" signal and a "don't
index it" signal at the same time. Verified live against `aayna_dev`:


`OutOfStock` in its Product schema (§4) — kept indexable because it's
expected to return, per this task's own §22 guidance. Bracelets/Hair
Accessories/Gift Sets products and categories are confirmed absent.

Zero test-data patterns (`TEST`, `TEST-IMP`, `TEST-HIST`, `TEST_Cat`,
`test-imported-e4c6`) found in the live sitemap — regression-checked by

## 5. Open Graph & social preview

**Real, previously undiscovered bug, fixed.** `frontend/public/index.html`'s
static OG/Twitter fallback tags used `%REACT_APP_PUBLIC_SITE_URL%` — not a
CRA-native substitution token (only `%PUBLIC_URL%` is; confirmed no custom
`InterpolateHtmlPlugin` exists in `craco.config.js`). Direct inspection of
the actual production build output proved this shipped as literal,
unreplaced text — `content="%REACT_APP_PUBLIC_SITE_URL%/"` — to every
crawler that doesn't execute JavaScript (Facebook, WhatsApp, LinkedIn link
unfurlers, and the very first paint before React hydrates). This never
showed up in prior milestones' work because that work exercised the
JS-executing runtime `useSeo()` path, which was always correct and
self-corrects to `window.location.origin` when the env var is unset.

**Fixed:** the three broken tags (`og:url`, `og:image`, `twitter:image`)
now hardcode `https://shopaayna.com` — this task's own stated domain
fallback — as absolute URLs. Re-verified against a real `npx craco build`
output (§13): no `%…%` tokens remain anywhere in the shipped HTML.

**Known, pre-existing, self-disclosed limitation — reported, not fixed:**
`frontend/public/og-image.svg` is a correctly branded, correctly sized
(1200×630) SVG, but its own top-of-file comment already flags this as a
"launch blocker for social sharing" — Facebook/WhatsApp/Twitter do not
reliably render SVG link previews. Replacing it with a real JPG/PNG is
launch-visual work, not an engineering fix, and out of this task's scope
(no new brand artwork was generated here).

## 8. Route integrity (invalid slugs, fake empty pages)

Two real bugs found and fixed:

**`ProductDetail.jsx` — stuck/indexable invalid-slug state.** The query
only destructured `isLoading`, never `isError`; on a 404 the component fell
through to a "Product not found" text with **no `noindex`** and a
default-title `<head>` — silently indexable. Fixed: added `isError`,
`retry: 1` (matches the existing `OrderConfirmation.jsx` convention — cuts
the default 3-retry ~7s settle time), a `notFound` state driving `noindex`,
and a proper not-found view with a link back to `/shop`.

**`Category.jsx` — fake indexable empty page on an unknown slug.** An
invalid category slug fell through to a generic `"Category"` title with a
real, indexable `robots` tag and an empty product grid — exactly the "fake
empty SEO page" this task's own instructions warned about. Fixed the same
way: real not-found state, `noindex`.

**Non-launch categories (Bracelets, Hair Accessories, Gift Sets) — real,
not invalid.** These resolve normally (real name/description, real
`TheEdit` UI) but carry no launch inventory and no matching nav tab in the
launch-scoped category strip. Decision: **noindex, not 404, not deleted**
— real catalogue that will return, presented honestly rather than hidden
behind a broken state. Mirrors the same launch-scope allowlist already
used by `Shop.jsx`/`Category.jsx` for filtering, now also applied in
`ProductDetail.jsx` for products in those categories (e.g. Pearl Charm
Bracelet) and in the backend sitemap (§3).

Live-verified via CDP against `aayna_dev` — see §12 for the full snapshot.

## 9. Canonical URL safety

`useSeo()`'s canonical (`upsertCanonical`) is built from `window.location.origin
+ window.location.pathname` — **query strings are never included.**
`/shop?category=earrings` and `/shop?search=hoop` both canonicalize to the
clean `/shop`, correctly collapsing duplicate-content query variants rather
than treating them as distinct pages. This was already correct
architecture, confirmed by code inspection and live CDP check, not a new
fix. No localhost/dev-port leakage was found in any canonical, OG, or
JSON-LD URL once §5's static-HTML fix landed — every checked route in §12
resolves to `http://localhost:3010/...` in this dev environment (the
correct, environment-appropriate value) and will resolve to the real
domain automatically once `REACT_APP_PUBLIC_SITE_URL` is set for
production, with no code change required.
